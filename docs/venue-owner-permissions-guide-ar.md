# دليل صلاحيات مالك القاعة وإدارة الاعتماد

## الغرض

يوثّق هذا الدليل التغييرات التي تم تطبيقها على مسار صلاحيات مالك القاعة بين لوحة تحكم فوشيا، وواجهة API، وتطبيق **Fuchsia Booking**، ويوضح الخطوات اليومية لاعتماد المالك أو إيقافه.

## ملخص التغيير

كانت صلاحية إدارة القاعات تعتمد عمليًا على `partnerPermissions.venueBookings`. هذا سبب ظهور رسالة **«حساب غير مخول لإدارة حجوزات القاعات»** لمالك قاعة معتمد عندما كانت صلاحية المتجر مضبوطة على `false`.

أصبح اعتماد مالك القاعة صلاحية مستقلة:

```text
venueOwners.status = "active"
        ↓
إدارة القاعات مفعلة في Fuchsia Booking
```

ولا تعيد صلاحيات المتجر كتابة صلاحية مالك القاعة النشط.

## مسار الصلاحية الكامل

```text
لوحة التحكم
  └─ اعتماد مالك القاعة (active)
       └─ venueOwners.status = active
            ├─ API: /api/venue-partner/* يسمح بالوصول
            ├─ API: /api/venue-partner/me يعيد venueBookings = true
            └─ تطبيق Fuchsia Booking يعرض وظائف إدارة القاعات
```

### 1. لوحة التحكم

تستخدم لوحة التحكم المسارات التالية:

- `GET /api/admin/venue-owners`: عرض طلبات مالكي القاعات.
- `PATCH /api/admin/venue-owners/:id`: تغيير الحالة إلى `pending` أو `active` أو `suspended`.
- `GET /api/admin/venue-owners/:id/details`: عرض تفاصيل المالك وقاعاته وحجوزاته.

تعيد استجابات لوحة التحكم الحقل:

```json
{
  "venueAccess": true
}
```

وتكون قيمته `true` فقط عندما تكون الحالة `active`.

### 2. واجهة API

قبل تنفيذ عمليات القاعات، يتحقق الخادم من:

1. وجود جلسة مستخدم صالحة.
2. وجود سجل مالك قاعة مرتبط بالمستخدم.
3. أن حالة السجل `active`.
4. أن الحساب ليس شريكًا محظورًا خارج مسار ملكية القاعة.

المسارات التشغيلية تشمل:

- `GET /api/venue-partner/me`
- مسارات إنشاء وتعديل القاعات.
- مسارات إدارة حجوزات القاعات.

المالك الذي حالته `pending` أو `suspended` لا يستطيع إدارة القاعات.

### 3. تطبيق Fuchsia Booking

يستخدم التطبيق استجابة `/api/venue-partner/me` لمعرفة الصلاحيات. للمالك النشط يجب أن تكون القيمة:

```json
{
  "account": {
    "permissions": {
      "venueBookings": true
    }
  }
}
```

يجب ألا يعتمد التطبيق على `partnerPermissions.venueBookings` وحدها لتقرير صلاحية مالك القاعة.

## دليل سريع: اعتماد مالك قاعة

1. سجّل الدخول إلى لوحة التحكم بحساب إداري.
2. افتح قسم **اعتماد الشركاء / أصحاب القاعات**.
3. اختر طلب مالك القاعة المطلوب.
4. راجع اسم النشاط ورقم التواصل وتفاصيل القاعات إن وجدت.
5. اضغط **اعتماد**.
6. تأكد من ظهور الشارتين:
   - `معتمد`
   - `إدارة القاعات مفعلة`
7. اطلب من المالك تسجيل الخروج والدخول في تطبيق Fuchsia Booking إذا كانت لديه جلسة قديمة.
8. افتح التطبيق وتحقق من ظهور وظائف القاعات والحجوزات.

رسالة النجاح المتوقعة في لوحة التحكم:

> تم اعتماد الشريك وتفعيل إدارة القاعات

## دليل سريع: إيقاف مالك قاعة

1. افتح قسم **أصحاب القاعات**.
2. اختر المالك النشط.
3. اضغط **إيقاف**.
4. تأكد من ظهور:
   - `موقوف`
   - `إدارة القاعات غير مفعلة`
5. اطلب من المالك إعادة فتح التطبيق أو تسجيل الدخول مجددًا.

رسالة النجاح المتوقعة:

> تم إيقاف الشريك وتعطيل إدارة القاعات

إيقاف المالك لا يحذف القاعات أو الحجوزات؛ يمنع فقط عمليات الإدارة الجديدة إلى أن تتم إعادة الاعتماد.

## حالات الحالة

| الحالة | صلاحية إدارة القاعات | الإجراء الإداري |
|---|---:|---|
| `pending` | لا | مراجعة الطلب ثم الاعتماد أو تركه قيد المراجعة |
| `active` | نعم | يمكن للمالك إدارة القاعات والحجوزات |
| `suspended` | لا | إعادة الاعتماد عند استيفاء الشروط |

## معالجة رسالة «حساب غير مخول»

إذا ظهرت الرسالة لمالك يدّعي أنه معتمد:

1. افتح لوحة التحكم وتحقق من أن الحالة **معتمد**.
2. تحقق من ظهور **إدارة القاعات مفعلة**.
3. اطلب من المستخدم تسجيل الخروج والدخول لتجديد الجلسة.
4. تحقق من استجابة:

   ```text
   GET /api/venue-partner/me
   ```

5. تحقق من أن `account.permissions.venueBookings` تساوي `true`.
6. إذا كانت الحالة في اللوحة `active` والاستجابة لا تزال خاطئة، راجع سجلات API وبيانات ربط المستخدم بسجل `venueOwners`.
7. لا تغيّر `partnerPermissions` كحل بديل؛ ملكية القاعة المعتمدة صلاحية مستقلة.

## قواعد السلامة

- لا تُعدّل `venueOwners.status` مباشرة في قاعدة البيانات إلا كإجراء طوارئ موثق.
- لا تحذف سجل المالك لإيقاف الوصول؛ استخدم `suspended`.
- لا تشارك توكنات الجلسات أو بيانات الدخول في التذاكر أو المحادثات.
- بعد أي تعديل صلاحيات، اختبر `/api/venue-partner/me` ثم افتح التطبيق بحساب اختباري.
- تغييرات المخطط غير مطلوبة لهذا المسار، ولا ينبغي حذف بيانات قائمة.

## اختبارات التحقق

تم التحقق من المسار بالاختبارات التالية:

- مالك نشط مع `venueBookings=false`: يسمح له بإدارة القاعات.
- شريك غير مالك مع رفض صريح: يبقى محظورًا.
- مالك موقوف: لا يسمح له بالوصول التشغيلي.
- حساب قديم أو JSON صلاحيات غير صالح: يحافظ على السلوك المتوافق.
- جميع اختبارات API: **10/10 ناجحة**.
- فحص TypeScript وبناء API: ناجحان.
- فحوص GitHub وبناء APK واختبار Android Emulator: ناجحة.
