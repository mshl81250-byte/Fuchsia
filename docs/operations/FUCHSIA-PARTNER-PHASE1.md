# Fuchsia Partner — المرحلة الأولى

**الحالة:** تطبيق Android مستقل بواجهة المرحلة الأولى وبناء Debug ناجح. الشيفرة على فرع `feat/android-expo-app`؛ لم تُنقل إلى `main` ولم تُنشر تغييرات API إلى الخادم الإنتاجي.

**فحص الخادم الحي (2026-10-08):** أعاد `GET /api/venue-partner/me` من دون رمز جلسة `HTTP 404 Cannot GET`؛ أي أن مسار الشريك غير منشور/غير موصول حاليًا. لذلك زر المعاينة المحلية متاح لاختبار الواجهة، أما تسجيل الدخول وإدارة البيانات الحقيقية فيتطلبان نشر API أولًا إلى بيئة اختبار.

## ما بُني

- تطبيق Android منفصل بحزمة `com.fuchsia.partner`، مبني بـKotlin وJetpack Compose، ويدعم اتجاه RTL والوضع الفاتح/الداكن حسب إعداد الجهاز.
- دخول بحساب Fuchsia الحالي، وتخزين رمز الجلسة مشفرًا عبر Android Keystore.
- طلب اعتماد مالك القاعة، ورسائل واضحة لحالتي الانتظار وعدم التفعيل.
- اختيار القاعة والجمهور، وتقويم شهري يميّز الأيام المتاحة والطلبات الجديدة والحجوزات المؤكدة والأيام المغلقة.
- تعديل أيام الدوام الأسبوعي، وإغلاق يوم أو فترة بسبب اختياري، وإعادة فتح الإغلاق.
- عرض طلبات الحجز وتفاصيل العميل والتاريخ والمدة وعدد الضيوف والمبالغ والإيصال.
- تأكيد الطلب بعد مراجعة الإيصال، أو رفضه مع سبب يُسجّل في سجل الحجز ويُرسل للعميل.
- معاينة محلية داخل Debug فقط بعلامة واضحة؛ بياناتها غير حقيقية ولا تُحفظ على الخادم.

## واجهات API المستخدمة أو المضافة

- `POST /api/auth/login`
- `GET /api/venue-partner/me`
- `POST /api/venue-partner/owner-request`
- `GET /api/venue-partner/bookings`
- `PATCH /api/venue-partner/bookings/:id` — يدعم سبب الرفض.
- `GET /api/venue-partner/venues/:id/calendar?month=YYYY-MM&audience=women|men` — تقويم خاص وموثّق للمالك، ويعمل حتى إذا كانت القاعة غير منشورة.
- `GET|PUT /api/venue-partner/venues/:id/availability` — الدوام الأسبوعي.
- `GET|POST /api/venue-partner/venues/:id/blackouts?month=YYYY-MM` — الإغلاقات.
- `DELETE /api/venue-partner/venues/:id/blackouts/:blackoutId` — إعادة فتح الأيام.

يتحقق الخادم من ملكية القاعة لكل عملية، ويرفض إغلاق فترة تتعارض مع حجز مؤكد أو حجز مؤقت نشط. إنشاء الإغلاق يقفل سجل القاعة ضمن معاملة لتقليل سباقه مع إنشاء حجز جديد.

## البناء والتشغيل

من جذر المشروع:

```bash
cd apps/partner/android
ANDROID_HOME=/usr/lib/android-sdk ANDROID_SDK_ROOT=/usr/lib/android-sdk ./gradlew :app:assembleDebug --no-daemon
```

يمكن تغيير عنوان API عند البناء باستخدام الخاصية أو متغير البيئة `FUCHSIA_API_BASE_URL`، مثل بيئة staging.

## قبل اختبار حجوزات حقيقية

1. نشر تغييرات `artifacts/api-server/src/routes/venue-partner.ts` إلى **staging** أولًا.
2. إعداد مالك نشط وربط قاعة اختبار بحسابه.
3. اختبار استلام إيصال التحويل، قبول/رفض الطلب، انتهاء مهلة الحجز، إغلاق الأيام، ومنع التعارض وإعادة الفتح.
4. لا يُستخدم وضع المعاينة للتسجيل أو الدفع؛ إجراءاته غير متصلة بالخادم.

لم تُضف إدارة الكوش والطاولات إلى هذا التطبيق بعد؛ تلك مرحلة تالية في المنتج الشريك الموحد.
