# تقرير اختبار صور منتجات الشريك

**التاريخ:** 2026-10-16
**النطاق:** تحقق الخادم من حقل `images` في مساري إدارة منتجات الشريك:

- `POST /api/vendor/products`
- `PATCH /api/vendor/products/:id`

## نتيجة الاختبار

تم تشغيل الأمر:

```bash
pnpm --filter @workspace/api-server test:product-images
```

النتيجة: **نجاح 4 اختبارات من أصل 4**.

| الحالة | المدخل | النتيجة المتوقعة | النتيجة الفعلية |
|---|---|---|---|
| قائمة فارغة | `[]` | قبول؛ الصور اختيارية للمسودة | ناجح |
| الحد الأقصى | 8 روابط صور HTTP/HTTPS | قبول | ناجح |
| تجاوز الحد | 9 روابط صور | رفض برسالة أن الحد الأقصى 8 صور | ناجح |
| رابط غير آمن | `ftp://...` أو نص غير صالح | رفض | ناجح |
| تكرار الروابط | نفس الرابط مرتين | حفظ رابط واحد بعد إزالة التكرار | ناجح |

## التحقق من التكامل البرمجي

تستخدم مسارات المنتجات دالة `normalizeProductImageList` قبل تمرير البيانات إلى `insertProductSchema` وقاعدة البيانات. لذلك ينطبق رفض الصورة التاسعة على الإنشاء والتعديل، وليس على اختبار منفصل غير مستخدم في المسارات.

كما نجح:

```bash
pnpm run typecheck
git diff --check
```

## ملاحظة عن الاختبار التشغيلي

هذا اختبار آلي لطبقة التحقق التي تستعملها المسارات. لم يتم إرسال طلب HTTP إلى قاعدة إنتاج أو تخزين صور فعلي؛ لأن المهمة الحالية لا تنشر API ولا تستخدم بيانات إنتاجية. اختبار HTTP الكامل يحتاج بيئة staging تحتوي قاعدة بيانات وتخزين صور مهيأين.
