# بدء المرحلة التالية لتطبيق الشريك

**الفرع:** `feat/admin-phase2-deep-management`
**النطاق المنفذ حتى الآن:** تحسين وضوح حداثة البيانات، تحمل انقطاعات الشبكة المؤقتة، وإظهار حالة الاتصال للشريك.

## التغيير الأول

تظهر مساحة الإيجار الآن وقت **آخر تحديث ناجح** بصيغة `HH:mm` بعد نجاح تحميل أي مجموعة من بيانات:

- منتجات الإيجار.
- حجوزات الإيجار.
- فترات الصيانة.
- التصنيفات.

يُحدّث الوقت تلقائيًا بعد:

- الضغط على زر التحديث.
- حفظ منتج.
- تغيير حالة نشر منتج.
- اتخاذ قرار على حجز.
- إضافة أو حذف فترة صيانة.
- تغيير المتجر المحدد.

إذا فشل تحميل كل المجموعات، لا يتم تغيير وقت آخر تحديث، حتى لا تظهر للمستخدم معلومة توحي بأن البيانات حديثة وهي ليست كذلك.

## تحسين موثوقية الشبكة

يُعاد تنفيذ طلب `GET` مرة واحدة فقط بعد تأخير قصير عند خطأ شبكة أو خطأ مؤقت من الخادم مثل `408`, `429` أو `5xx`. لا تُعاد محاولة `POST` أو `PATCH` أو `DELETE` تلقائيًا، لأن تكرارها قد يكرر رفع صورة أو قرار حجز أو تعديل منتج.

إذا فشلت قراءة المنتجات أو الحجوزات أو الصيانة بسبب اتصال مؤقت، يظهر تحذير واضح داخل مساحة الإيجار. وعند وجود بيانات محملة سابقًا يوضّح التحذير أن المعروض قديم، أما عند الفشل قبل أول تحميل فيطلب من الشريك التحقق من الإنترنت وإعادة التحديث.

## حدود الفحص

- فحوصات TypeScript وبناء API واختبار حد الصور تعمل من بيئة Sandbox.
- بناء Kotlin/Android الكامل يحتاج Android SDK غير متوفر حاليًا في Sandbox؛ لذلك يجب تشغيل `./gradlew :app:assembleDebug` في بيئة Android/CI قبل إصدار APK.
