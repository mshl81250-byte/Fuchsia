# تطبيق Fuchsia Boutique الأصلي — Android

هذا مجلد تطبيق Android أصلي بلغة **Kotlin** وواجهة **Jetpack Compose**، والتنقل عبر **Navigation Compose (`NavController` و`NavHost`)**. شاشة الترحيب والمصادقة والرمز وكتالوج التصنيفات تتصل بخادم API الفعلي؛ لا توجد بيانات مصطنعة لمسار الدخول أو التسجيل.

## المكونات المنفذة في هذه المرحلة

- ترحيب متجاوب يعرض الشعار الأصلي مرة واحدة، ويحدد ارتفاع الصورة بحسب المساحة المتاحة، ويثبت أزرار المتابعة أسفل الصفحة بدل تكديس المحتوى في أعلى الشاشة.
- انتقالات شاشات طبيعية انزلاقية مع دعم زر الرجوع في Android، بدل تقليب صور/شرائح.
- دخول، طلب إنشاء حساب، والتحقق من OTP الحقيقي عبر `/api/auth/*`؛ خيار الضيف ينشئ جلسة ضيف فعلية في الخادم.
- تخزين الجلسة بتشفير AES-GCM ومفتاح Android Keystore.
- الصفحة الرئيسية والتصنيفات والمنتجات المميزة تُحمّل من API المشروع.
- سلة متصلة بـ`/api/cart`، وتعديل الكميات/الحذف، وملخص السعر ورسوم التوصيل.
- إتمام طلب متصل بـ`/api/orders`، واختيار الدفع عند التوصيل أو التحويل الجزئي/الكامل، ورفع إيصال الدفع إلى الخادم.
- تحديد نقطة التوصيل على خريطة تفاعلية حقيقية (MapLibre + OpenFreeMap)، أو جلب موقع الجهاز عبر GPS مع إذن وقت الاستخدام، ثم تمرير الإحداثيات المعتمدة مع الطلب.
- طلب هدية يضيف المنتجات إلى السلة نفسها، ثم يمرر بيانات المستلم والرسالة وإخفاء السعر للطلب.
- حجز طاولة عبر Navigation Compose، مع اختيار الفرع والموعد وعدد الضيوف وإرسال الطلب إلى `/api/reservations` برمز Bearer موثق؛ تُربط الحجوزات بحساب الجلسة على الخادم.
- استثناء الاختبار الوحيد الذي طلبه مالك التطبيق: يعرض الخادم رمز OTP على شاشة التحقق عندما يطلبه العميل عبر رأس `X-Fuchsia-OTP-Debug`.

## البناء

المطلوب: JDK 17 أو أحدث وAndroid SDK مع المنصة 37 وأدوات البناء 36.0.0.

```bash
cd apps/mobile/android
printf 'sdk.dir=%s\n' "$HOME/android-sdk" > local.properties
./gradlew :app:assembleDebug
```

لإنشاء APK Release موقّع بمفتاح Fuchsia المحلي:

```bash
cd apps/mobile
./scripts/build-release-apk.sh
```

يحافظ إصدار Kotlin الحالي على `applicationId = com.fuchsia.platform` ومفتاح Release نفسه للنسخة السابقة، مع `versionCode = 4` و`versionName = 1.2.0`، حتى يُثبّت كتحديث فوق التطبيق الموجود بدل إنشاء تطبيق ثانٍ. لا تُحفظ كلمات المرور أو ملف المفتاح في Git.

### الخرائط والموقع

تستخدم شاشة الإتمام MapLibre Android وخريطة OpenFreeMap بأسلوب `positron`، من دون مفتاح API. يستطيع العميل تحريك الخريطة وتكبيرها حتى يضع الدبوس في موقع التسليم، ثم يعتمد الإحداثيات؛ كما يستطيع طلب الموقع الحالي عبر GPS بعد منح إذن الموقع أثناء الاستخدام. يلزم اتصال بالإنترنت لتحميل الخريطة. يظهر الإسناد المطلوب إلى OpenFreeMap وOpenMapTiles وOpenStreetMap داخل الواجهة. الخدمة العامة تسمح بالاستخدام التجاري بلا مفتاح لكنها لا تقدم SLA؛ إذا تطلب التشغيل مستقبلًا ضمان توافر تعاقديًا، يمكن تبديل عنوان style إلى مزوّد أو استضافة مُدارة.

### تفعيل API حجز الطاولات

يتضمن المصدر مسار `/api/reservations` وجداول الحجوزات والجلسات وأحداث تتبع الطلب. عند بدء إصدار API الجديد، ينفذ `runMigrations()` ترحيلًا إضافيًا آمنًا ينشئ الجداول المفقودة دون حذف بيانات قائمة؛ يلزم قبل النشر التأكد من أن `DATABASE_URL` يشير إلى قاعدة الإنتاج الصحيحة وأخذ نسخة احتياطية وفق إجراءات المشغل. نشر ملفات المصدر وحده لا يحدّث الخادم المنشور. شاشة التطبيق لا تدّعي تأكيد الحجز، بل تعرضه كطلب بانتظار رد الفرع.
