# فوشيا — Fuchsia Platform

منصة عربية RTL لتجهيز المناسبات والهدايا الفاخرة. يجمع المشروع بين متجر العملاء، السلة وإتمام الطلب، الدفع اليدوي عبر المحافظ الإلكترونية، تحديد موقع التوصيل، متابعة الطلبات، ولوحة تحكم الإدارة.

> **حالة المشروع:** نسخة تشغيلية قابلة للبناء والنشر. قاعدة البيانات المستخدمة في النسخة الحالية هي **MySQL** عبر Drizzle ORM، وليست PostgreSQL.

## روابط مهمة

- المستودع: <https://github.com/mshl81250-byte/Fuchsia-Platform>
- المعاينة/الموقع المنشور: <https://fuchsia-x7dwxpzd.manus.space>
- الفرع الرئيسي: `main`
- أحدث مصدر لتطبيق Android الأصلي: الفرع [`feat/android-expo-app`](https://github.com/mshl81250-byte/Fuchsia-Platform/tree/feat/android-expo-app)؛ لم يُدمج إلى `main`.

## المزايا

### واجهة العملاء

- واجهة عربية كاملة باتجاه RTL.
- تصفح المنتجات والتصنيفات والمتاجر والعروض.
- البحث والفلاتر والمفضلة والسلة.
- إنشاء حساب عبر البريد الإلكتروني ورمز تحقق صالح لمدة **3 دقائق**.
- تسجيل الدخول أو الدخول كزائر.
- إتمام الطلب مع:
  - الاسم ورقم الهاتف والعنوان.
  - تحديد موقع التوصيل عبر GPS.
  - خط العرض وخط الطول ضمن نطاق صنعاء.
  - ملاحظات التوصيل وبيانات الهدية.
- متابعة الطلبات وحالاتها.
- ظهور اسم الموصّل ورقم جواله عند انتقال الطلب إلى حالة التوصيل.

### الدفع اليدوي

يدعم الطلب دفعًا كاملًا أو جزئيًا عبر المحافظ الإلكترونية المعتمدة:

- جيب
- جوالي
- موبايل موني
- محفظتي
- كاش
- فلوسك

يعرض النظام اسم المحفظة ورقم حساب متجر فوشيا وتعليمات التحويل، ثم يسمح للعميل بإدخال رقم العملية وإرفاق إيصال التحويل. يبقى الطلب في حالة `pending_review` حتى تراجعه الإدارة.

### لوحة الإدارة

- عرض الإحصائيات والطلبات والعملاء والكوبونات.
- مراجعة طلبات الدفع اليدوي والإيصالات.
- تحديث حالة الطلب.
- إدخال اسم الموصّل ورقم جواله.
- إدارة محافظ الدفع وأرقام الحسابات والتعليمات والأيقونات.
- إدارة المنتجات والمتاجر والتصنيفات والكوبونات.
- إعدادات قنوات البريد وWhatsApp.
- مصادقة الإدارة من الخادم باستخدام جلسة موقعة وملف تعريف Cookie، وليس مقارنة كلمة المرور داخل المتصفح.

## التثبيت المحلي

### 1. استنساخ المشروع

```bash
git clone https://github.com/mshl81250-byte/Fuchsia-Platform.git
cd Fuchsia-Platform
```

### 2. تثبيت الاعتماديات

```bash
pnpm install --frozen-lockfile --ignore-scripts
```

> يستخدم المشروع `pnpm` في workspace. لا تستخدم `npm install` أو `yarn install` بدلًا منه.

### 3. إعداد متغيرات البيئة

انسخ النموذج إلى ملف محلي:

```bash
cp .env.example .env
```

عدّل `.env` وضع القيم الحقيقية محليًا أو في خدمة الأسرار الخاصة ببيئة النشر. **لا ترفع ملف `.env` إلى GitHub.**

| المتغير | مطلوب | الوصف |
|---|---:|---|
| `DATABASE_URL` | نعم | رابط اتصال MySQL، مثل `mysql://user:password@host:3306/database` |
| `PORT` | لا | منفذ الخادم محليًا، الافتراضي المعتاد `5000` |
| `SESSION_SECRET` | نعم | سر عشوائي طويل لتوقيع جلسات الإدارة ورموز التحقق |
| `ADMIN_INITIAL_PASSWORD` | عند تشغيل seed | كلمة مرور الإدارة الأولية، 12 حرفًا على الأقل |
| `RESEND_API_KEY` | للبريد | مفتاح Resend لإرسال رموز التحقق والإشعارات |
| `EMAIL_FROM` | للبريد | عنوان المرسل الموثق في Resend |
| `EMAIL_LOGO_URL` | اختياري | رابط HTTPS لشعار فوشيا في قالب البريد |
| `WHATSAPP_ACCESS_TOKEN` | اختياري | رمز WhatsApp Business Cloud API |
| `WHATSAPP_PHONE_NUMBER_ID` | اختياري | معرّف رقم WhatsApp المرسل |

لتوليد قيم عشوائية محليًا:

```bash
openssl rand -base64 48
```

### 4. إنشاء مخطط قاعدة البيانات

تأكد من أن `DATABASE_URL` مضبوط، ثم نفّذ دفع مخطط Drizzle إلى قاعدة MySQL:

```bash
pnpm --filter @workspace/db run push
```

> نفّذ `push` بحذر في بيئة الإنتاج. يفضّل استخدام migrations منظمة قبل أي تغيير كبير على قاعدة بيانات حية.

### 5. إضافة البيانات الأولية

تحتاج عملية seed إلى `ADMIN_INITIAL_PASSWORD` مضبوطًا. سكربت الخادم يحافظ على حسابات العملاء الموجودة ويمسح بيانات الكتالوج والبيانات التشغيلية التي يعيد إنشاءها.

```bash
ADMIN_INITIAL_PASSWORD='ضع-كلمة-مرور-قوية-هنا' \
pnpm --filter @workspace/scripts exec tsx artifacts/api-server/src/seed.ts
```

أو عبر بيئة محمّلة مسبقًا:

```bash
pnpm --filter @workspace/scripts exec tsx artifacts/api-server/src/seed.ts
```

**تنبيه:** لا تشغّل seed على قاعدة إنتاجية دون فهم الجداول التي يعيد تهيئتها ووجود نسخة احتياطية.

## تدفق الطلب والدفع اليدوي

التدفق الوظيفي المقصود:

1. يختار العميل منتجًا ويضيفه إلى السلة.
2. يفتح صفحة إتمام الطلب.
3. يحدد الاسم والهاتف والعنوان.
4. يحدد موقعه عبر GPS أو يثبت الموقع على الخريطة.
5. يختار الدفع عند الاستلام أو الدفع الكامل/الجزئي عبر محفظة.
6. عند الدفع اليدوي، يختار المحفظة ويشاهد رقم الحساب والتعليمات.
7. يدخل رقم العملية ويرفع إيصال التحويل.
8. ينشئ النظام الطلب بحالة دفع `pending_review`.
9. تراجعه الإدارة وتحدّث حالة الدفع والطلب.
10. عند التجهيز، تدخل الإدارة اسم الموصّل ورقم جواله وتحول الطلب إلى التوصيل.
11. يرى العميل بيانات الموصّل وحالة طلبه.

القيمة الحالية لرقم حساب المحافظ في البيانات الأولية:

```text
778360009
```

يمكن تعديل أرقام المحافظ من لوحة الإدارة بعد تسجيل دخول إداري صحيح.

## حالات الطلب والدفع

### حالات الطلب الشائعة

- `received` — تم استلام الطلب.
- `processing` — قيد التجهيز.
- `ready` — جاهز للتسليم.
- `delivering` — جاري التوصيل.
- `delivered` — تم التسليم.
- `cancelled` — ملغى.

### حالات الدفع

- `unpaid` — لم يتم الدفع بعد.
- `pending_review` — بانتظار مراجعة إيصال التحويل.
- `paid` — تمت الموافقة.
- `rejected` — تم رفض الدفع.

## أهم مسارات API

| الطريقة | المسار | الغرض |
|---|---|---|
| `GET` | `/api/healthz` | فحص جاهزية الخادم |
| `GET` | `/api/products` | عرض المنتجات |
| `GET` | `/api/payment-wallets` | المحافظ النشطة للعملاء |
| `POST` | `/api/auth/guest` | إنشاء جلسة زائر |
| `POST` | `/api/auth/register/request-code` | طلب رمز تسجيل عبر البريد |
| `POST` | `/api/auth/register/verify-code` | التحقق من الرمز وإنشاء الحساب |
| `POST` | `/api/auth/login` | دخول العميل |
| `GET` | `/api/cart?sessionId=...` | عرض السلة |
| `POST` | `/api/cart` | إضافة منتج للسلة |
| `POST` | `/api/orders` | إنشاء الطلب |
| `GET` | `/api/orders?sessionId=...` | عرض طلبات الجلسة |
| `POST` | `/api/admin/auth/login` | دخول الإدارة بجلسة خادم |
| `POST` | `/api/admin/auth/logout` | إنهاء جلسة الإدارة |
| `GET` | `/api/payment-wallets/all` | المحافظ للإدارة |

تتطلب مسارات الإدارة جلسة الإدارة الموقعة. لا تعتمد على قيمة `localStorage` وحدها لمنح صلاحيات API.

## النشر

النشر الإنتاجي يحتاج إلى:

1. قاعدة MySQL مُدارة.
2. متغيرات البيئة في مدير الأسرار، لا داخل Git.
3. `SESSION_SECRET` عشوائي وطويل.
4. `RESEND_API_KEY` صالح وعنوان `EMAIL_FROM` موثق.
5. `ADMIN_INITIAL_PASSWORD` مضبوط فقط عند إنشاء حساب الإدارة أو إعادة seed مقصودة.
6. فحص `GET /api/healthz` كمسار صحة غير محمي.
7. فتح المنفذ الذي توفره بيئة التشغيل عبر `PORT`.

المشروع يحتوي على `Dockerfile` و`.gcloudignore` و`app.config.ts` لتسهيل النشر بالحاويات. لا تضمّن أسرارًا في Dockerfile أو أوامر build أو ملفات الواجهة، لأن قيم الواجهة قد تصبح قابلة للقراءة من المتصفح.

## الأمان

- لا ترفع `.env` أو ملفات مفاتيح أو إيصالات حقيقية إلى المستودع.
- استخدم مدير أسرار في الإنتاج.
- غيّر كلمة مرور الإدارة الأولية قبل الإطلاق، ولا تستخدم قيمة بسيطة.
- لا تشارك `SESSION_SECRET` أو `RESEND_API_KEY` أو رمز WhatsApp.
- راجع صلاحيات الإدارة ومسارات الطلبات قبل فتح الموقع للجمهور.
- استخدم HTTPS في الإنتاج.
- احتفظ بنسخ احتياطية قبل تغييرات قاعدة البيانات أو تشغيل seed.
- لا تعتمد على بيانات العميل مثل `userId` أو `sessionId` وحدها عند بناء صلاحيات نهائية؛ يجب ربطها بجلسة موثقة وعزل ملكية البيانات.
- راجع نتائج `pnpm audit` بانتظام، خصوصًا أدوات البناء وتوليد كود OpenAPI.

### فحص الأسرار والاعتماديات

```bash
rg -n -i --hidden \
  --glob '!node_modules/**' \
  --glob '!dist/**' \
  --glob '!.git/**' \
  '(api[_-]?key|access[_-]?token|private[_-]?key|password[[:space:]]*[:=]|-----begin)' .

pnpm audit --audit-level high
```

نتيجة البحث لا تعني أن كل تطابق سر؛ بعض التطابقات تكون أسماء حقول أو نماذج توثيق. راجع كل نتيجة يدويًا.

## استكشاف الأخطاء

### فشل الاتصال بقاعدة البيانات

- تحقق من وجود `DATABASE_URL`.
- تحقق من أن الرابط بصيغة MySQL المناسبة.
- تحقق من صلاحية المستخدم والمنفذ والجدار الناري.
- في قواعد MySQL المُدارة قد تحتاج إلى إعداد SSL حسب مزود الخدمة.

### رمز البريد لا يصل

- تحقق من `RESEND_API_KEY`.
- تحقق من أن `EMAIL_FROM` نطاق موثق.
- راجع سجلات الخادم.
- تحقق من أن رمز التحقق لم يتجاوز مدة 3 دقائق.

### دخول الإدارة يفشل

- تأكد من وجود المستخدم الإداري في قاعدة البيانات.
- تأكد من أن كلمة المرور المستخدمة هي نفسها التي استُخدمت في seed عبر `ADMIN_INITIAL_PASSWORD`.
- تحقق من وجود `SESSION_SECRET`.
- امسح Cookie الجلسة القديمة وأعد المحاولة.

### لا تظهر المحافظ أو المنتجات

- تحقق من `GET /api/products` و`GET /api/payment-wallets`.
- شغّل مخطط قاعدة البيانات.
- نفّذ seed بعد أخذ نسخة احتياطية.
- راجع سجلات الخادم.
